# 提示词与修补策略

提示词全文在 `scripts/prompts.py`。本文说明**为什么这么写**，以及效果不对时该拧哪个旋钮。

## 1. 三个阶段为什么分开

| 阶段 | 输入 | 输出 | 模型的自由度 |
|---|---|---|---|
| distill | 一段原文（约 2000 字，带 R 行号） | 角色表 + 剧情线 + 可拍场景卡 | 认人、抽线、切场景、把叙述改写成动作 |
| semantic | 蒸馏稿 | 语义 md | **零自由度**：确定性投影，不调模型 |
| plan | 语义 md + 槽位名单 | 1 分钟计划 JSON | 只能选主线、排 12 段；不能造台词、不能自创槽位 |

合并成一步会让模型同时处理「理解剧情 + 改写画面 + 排版 + 数时长」，小模型必崩。
分开后每一步只有一个判断维度；semantic 干脆交给程序，两层永远不会不同步。

## 2. distill 提示词的关键约束

- **先认人再切场景**：角色表在场景卡之前，模型必须先想清「谁在场」，再决定怎么切。
- **标志物必填**：画面上认得出的特征（刀疤脸、斗笠、背后刀剑），是后面建设定表和配参考图的依据。
- **可拍画面带行号**：每条 `- R#### 动作`，把改写锚回原文；没有行号就无法核对是否漏戏。
- **改写而不是摘抄**：「杀气腾腾」这类词直接禁用，逼模型写「刀锋压低，指节捏白」。
- **剧情线四段**：起／承／转／合强制填，防止模型只写「发生了什么」而丢掉因果与冲突。

## 3. semantic 提示词的关键约束（`--raw` 老路才用）

- **编号写死在示例里**：`### {ep}-S01`、`{ep}-L001`，模型只需递增。
- **台词只取引号内**：明确「去掉外层引号与『人物道：』前缀」，避免把「沈稳的说」写进说话人。
- **语气单列**：原文动作/状态移到第 4 列，后续 `delivery` 直接用。
- **论坛噪音丢弃**：日期、`----`、`N 回复：`、网址不进产物。

## 4. plan 提示词的关键约束

- **先给槽位合法名单**，再给结构。名单之外的取值一律作废，这是防自创场景/人物的第一道闸。
- **条数精确**：「恰好 N 条，不多不少；少了要拆，多了要合」。不给数字模型会输出 8 条或 14 条。
- **action 6–25 字 + 禁用词清单**：只写拍得到的。禁用词直接列在提示词里，和 `BAN_ACTION` 保持一致。
- **台词 ≤21 字 + 溯源规则**：能逐字用就填 `line`，超长压缩就填 `""`。这条让「引用」和「改写」永远可区分。
- **每条视频 8–14 条台词**：防止全程念白，也防止 12 段只有一句。

## 5. 回喂与修补（三档）

```
第 1 版 ──校验──▶ 通过 → 收口
             │
             ├─ 错误全是「第N条视频 第M段 …」
             │     → 定点修补：只回喂这几段的当前值，要 {"fixes":[…]}
             │
             ├─ 错误是全局的（条数不对、槽位非法、缺字段）
             │     → 整份重出：回喂错误清单，要求完整 JSON
             │
             └─ 错误只剩「超 21 字 / 原文不符 / 超长」
                   → 不再调模型，交给 sanitize_plan 确定性收口
```

**为什么定点修补**：整份重出时模型常把已经对的段改坏（改一处台词，顺手改了别处的动作）。按段回喂能把破坏面限制在违规段。

**为什么长度问题不重试**：裁到 21 字是确定性操作，重试只会浪费一次推理，还可能引入新错。

## 6. 调优旋钮

| 想要 | 改哪里 |
|---|---|
| 某集多切/少切几条视频 | `--videos E01=3` 或 `story.json` 的 `videos` |
| 台词太密/太稀 | `prompts.plan_user` 第 7 条（8–14 条） |
| 动作太抽象 | 扩充 `contract.BAN_ACTION`，并在提示词第 4 条同步加例 |
| 某类词总被念出来 | 加进 `BAN_ACTION`；verify 会拦住 |
| 模型爱自创场景 | 补 `LOCATION_HINTS`，并检查 `SCENES` 是否覆盖原文地点 |
| 输出总是非 JSON | 端点无约束解码；`llm.parse_json` 已容错，仍失败会强制一次格式纠正 |
| 速度慢 | `chat_template_kwargs.enable_thinking=false`（默认开）；并发 `--workers 3` |

## 7. 提示词改动纪律

改 `prompts.py` 后必须同步三处，否则校验与提示词会脱节：

1. `contract.BAN_ACTION`（拦什么）
2. `prompts.plan_user` 的硬性规则编号（告诉模型什么）
3. `references/01_格式契约.md` 的约束表（告诉人什么）

先跑一集试点（`--episodes E01 --workers 1`），看 `run.log` 里第几版通过、剩余问题是什么，再决定是否全量。
